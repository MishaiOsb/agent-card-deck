How to build, present, and deliver agent specification decks

Overview

What is the Agent Card Deck?

The Agent Card Deck is an interactive web app for specifying, presenting, and delivering AI agent implementations to clients. It turns our methodology into a structured, client-facing presentation that walks through why we do things (See. Then Do.) before showing what we're building (individual agent cards).

It replaces loose docs and slide decks with a single tool that handles the full journey: spec, present, sign-off, and export.

Live app: mishaiosb.github.io/agent-card-deck — works on any device, no login needed.

Step 1: Client Setup

Click Create New Deck on the home page. Fill in the client details:

  • Company Name (required) — appears on the cover slide and throughout
  • Project Name — e.g. "AI Agent Implementation Phase 1"
  • Primary Contact (required) — the client stakeholder
  • Contact Role / Email / Industry — optional context fields
  • Meeting Date — defaults to today, shown on cover
  • Presenter — your name, shown on cover

Click Continue to Deck Builder when done.

Step 2: Deck Builder

This is the main workspace. The left sidebar shows your agent cards and backlog; the right panel is the editor.

Adding an Agent

Click + Add Agent Card and pick one of the 5 agent types:

Support Agent

Calls, tickets, chat — customer-facing interactions

Analyst Agent

Data analysis, reporting, revenue discovery

Computer Use Agent

Browser automation, data entry, system tasks

Sales/Outreach Agent

Lead nurturing, pipeline, outbound, demos

Task/Automation Agent

Workflow automation, scheduled jobs, orchestration

Section A — Universal Specification

Every agent has these fields regardless of type:

  • Agent Name — a descriptive name (e.g. "Inbound Triage Agent")
  • Purpose — what is this agent's primary objective?
  • 6 Agreed Steps — the exact workflow this agent follows (max 6 steps)
  • Approved Copy — scripts, templates, or messaging it uses
  • Escalation Rule — when does this agent hand off to a human?
  • Out-of-Scope List — things this agent explicitly does NOT handle

Section B — Type-Specific Parameters

Each agent type has its own set of parameters. For example, a Support Agent has call direction, greeting script, channels, and operating hours. An Analyst has data sources, analysis type, and report frequency. Fill in what's relevant — not everything is required.

Backlog

Use the Out-of-Scope Backlog at the bottom of the sidebar to log items that came up but are out of scope for this phase. Each item gets a priority (Low / Medium / High). These appear on the Backlog slide in the presentation.

Agent Actions

  • Duplicate — copy an agent card (useful for similar agents)
  • Remove — delete an agent from the deck
  • Rev 0/3 — shows how many of the 3 allowed revisions have been used

Client Sign-Off

Each agent slide has a sign-off checkbox at the bottom. Tick it during the meeting when the client approves that agent's spec. The Summary slide shows the sign-off count.

The "See. Then Do." Methodology

Slides 2–4 establish our core principle: Insights Before Action — Always. These are static methodology slides that require no data entry. Use them to set context before diving into the individual agents.

How to Present These Slides

Stage 1: See (Insights)

We start by deploying Analyst Agents that are read-only. No workflow changes, no risk. They observe your existing data and surface what's hidden — missed revenue, time sinks, quality gaps.

Stage 2: Do (Action)

Only after we have evidence do we deploy Interactive or Action agents. These agents talk to customers, operate systems, and automate tasks — but only where the data tells us to.

Three Dimensions of Value

Every agent we build maps to at least one of these:

Revenue (£)

See: Detect hidden revenue
Do: Capture that revenue

Capacity (C)

See: Find the time sinks
Do: Eliminate those drains

Experience (E)

See: Expose quality gaps
Do: Fix the experience

Talking point: "We never automate what we don't understand. Analyst agents observe first. Only then do Interactive and Action agents execute."

Fix vs Change Framework

This appears on the Delivery Gates slide. It sets expectations for what happens after delivery:

Fix (In-Scope)

The agent isn't performing to the signed spec. This is a fix, not a change — it's covered.

Examples: wrong copy, escalation not triggering, steps not followed

Change Request

New work not in the Agent Card. Needs to be assessed and scoped separately.

Examples: new feature, different workflow, extra integration

Out-of-Type

Requires a completely new agent card. The request falls outside this agent's type.

Examples: support agent asked to do sales, analyst asked to handle calls

Why this matters: This framework prevents scope creep. If the client asks for something after sign-off, you categorise it here. Fixes are covered. Changes go to backlog. Out-of-type means a new card.

Step 4: Exporting & Sharing

Export Options

From the presenter toolbar:

  • PDF — downloads a multi-page PDF with all slides including Seethendo methodology pages
  • PPTX — downloads a PowerPoint file with branded master slides, ready for stakeholders

Both exports include all slides: cover, methodology, overview, agent cards, gates, timeline, backlog, and summary.

Share Link

Click Share to generate a URL that contains the full deck data. Anyone with the link can view the presentation — no login or setup needed.

Note: The share link is a snapshot. If you edit the deck after sharing, existing links won't update. Generate a new link after making changes.

Recommended Delivery Flow

  1. Present live in the meeting using the web app
  2. Collect sign-offs on each agent during the call
  3. Export PDF/PPTX and send as the formal record
  4. Share the link for anyone who missed the meeting

Tips for Running a Good Meeting

  • Start with methodology — don't skip slides 2–4. They set the foundation and make the rest easier to discuss.
  • Use dark mode for screen-sharing on calls — it's easier on the eyes and looks more polished.
  • Switch to light mode for in-person projectors where dark backgrounds wash out.
  • Fill in agent names before the meeting — even if Section B is incomplete, having named agents makes the overview slide useful.
  • Use the backlog — when a client raises something out of scope, add it to backlog immediately. This shows you're listening without derailing the agenda.
  • Get sign-off live — tick the checkbox while the client is watching. It creates accountability in the moment.
  • Export immediately after — send the PDF within an hour of the meeting ending.

Delivery Gates

Revision Policy

Maximum 3 revisions per agent. Fixes for in-scope issues are covered. Change requests are logged for future phases. Out-of-type requests require a new agent card.
